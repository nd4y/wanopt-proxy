# wanopt-proxy

[🇬🇧 English](README.md) | 🇷🇺 **Русский**

WAN-оптимизатор на **QUIC**. Клиент (Windows) поднимает локальный прокси
**SOCKS5 / HTTP**; трафик мультиплексируется в один аутентифицированный
QUIC-туннель и выходит наружу на сервере (Linux / Docker).

## Почему QUIC

- **Forward secrecy бесплатно** — QUIC обязывает использовать TLS 1.3 с эфемерным ECDHE.
- **Нет head-of-line blocking** — каждое проксируемое TCP-соединение это отдельный
  QUIC-поток, поэтому один поток с потерями не тормозит остальные (в отличие от TCP-в-TCP).
- **Ретрансляция UDP** — UDP-потоки едут в QUIC DATAGRAM-фреймах (SOCKS5 UDP ASSOCIATE).
- **Миграция соединения и keepalive** — переживает смену IP или сети на клиенте.

## Модель безопасности (PSK + пиннинг, без PKI)

- Сервер предъявляет **самоподписанный сертификат**; клиент пиннит хеш его
  **SPKI SHA-256**. Ни CA, ни слепого доверия через `InsecureSkipVerify`.
- Поверх запиненного канала TLS 1.3 обе стороны доказывают знание общего
  **PSK** через `HMAC(PSK, метка ‖ TLS-exporter)`. Экспортер уникален для каждой
  сессии, поэтому доказательство **невоспроизводимо повторно** и аутентифицирует
  **обе** стороны.

## Структура

```
cmd/server    демон выхода (Linux/Docker)
cmd/client    входной прокси (Windows)
cmd/keygen    генерация PSK + сертификата сервера и пина
internal/protocol  кодек адресов + фреймирование потоков и датаграмм
internal/tunnel    TLS (самоподписанный + пиннинг), аутентификация по PSK, настроенный quic.Config
internal/server    QUIC-листенер, TCP-релей, UDP NAT, применение ACL
internal/client    подключение и аутентификация QUIC + фоновое переподключение + heartbeat
internal/proxy     SOCKS5 (+UDP ASSOCIATE) и HTTP (CONNECT/forward)
internal/acl       политика разрешений по назначению (домен / IP-CIDR / порт)
internal/compress  адаптивное сжатие потоков по результатам пробы
internal/metrics   коллекторы Prometheus + трассировщик quic-go (RTT/потери/cwnd)
internal/decoy     сайт-прикрытие на HTTP/3 (встроенное файловое облако / прокси / каталог)
```

## Оптимизации и возможности

- **Контроль доступа (сервер)** — разрешение и запрет назначений по суффиксу
  домена, IP/CIDR и порту, и для TCP, и для UDP. Запрет побеждает; непустой
  список разрешений работает как белый список.
- **Устойчивый туннель (клиент)** — фоновый обслуживающий цикл держит поднятым
  одно аутентифицированное соединение, переподключаясь с экспоненциальной
  задержкой. Heartbeat по управляющему потоку обнаруживает мёртвый туннель за
  несколько секунд. *Активные TCP-потоки пережить обрыв туннеля не могут
  (удалённый сокет живёт на сервере); вместо этого обслуживающий цикл добивается
  быстрого восстановления для новых запросов.*
- **Пропускная способность на больших BDP** — крупные окна приёма потока и
  соединения (по умолчанию 16/24 МиБ, настраиваются) не дают простаивать длинным
  толстым каналам. *Замечание: quic-go v0.48 использует внутри CUBIC и не даёт
  публичного переключателя на BBR, поэтому рычаг здесь — размер окна, а не
  алгоритм контроля перегрузки.*
- **Адаптивное сжатие** — каждое направление пробует первый фрагмент и применяет
  DEFLATE только если образец действительно сжимается, так что TLS, видео и
  архивы проходят нетронутыми (без лишнего CPU и без раздувания).
- **Метрики и 0-RTT** — Prometheus-эндпоинт `/metrics` отдаёт по каждому туннелю
  RTT, окно перегрузки, потери пакетов, счётчики байт и статистику потоков и
  переподключений. Возобновление сессии через 0-RTT ускоряет переподключение;
  ради защиты от повторов аутентификация и трафик прокси никогда не уходят как
  ранние данные 0-RTT.
- **Полная маскировка под HTTP/3 и сайт-прикрытие** — сервер *является*
  настоящим HTTP/3-сервером. Обычные запросы (браузеры, сканеры, активные
  пробы) получают правдоподобную страницу входа в самостоятельно размещённое
  файловое облако («CloudVault»); прикрытие настраивается (`builtin` /
  обратный `proxy` на реальный сайт / статический `dir` / `off`). Потоки туннеля
  спрятаны за зарезервированным типом HTTP/3-фрейма и маршрутизируются через
  `StreamHijacker`, а клиент проводит настоящее h3-рукопожатие SETTINGS — так что
  для любой пробы туннель и настоящее файловое облако неразличимы. Запускайте на
  `:443` с ALPN `h3` для полного прикрытия.

## Быстрый старт

```sh
# 1. Сгенерировать секреты (пишет cert.pem/key.pem, печатает psk и пин)
go run ./cmd/keygen -cert

# 2. Конфигурация сервера (configs/server.yaml): указать psk, cert_file, key_file
go run ./cmd/server -config configs/server.yaml

# 3. Конфигурация клиента (configs/client.yaml): указать server, psk, pin
go run ./cmd/client -config configs/client.yaml

# 4. Направить браузер или приложение на socks5://127.0.0.1:1080 либо http://127.0.0.1:8080
curl -x socks5h://127.0.0.1:1080 https://example.com
```

### Docker (сервер)

```sh
docker compose up --build -d
```

## Сборка нативных бинарников

```sh
# Сервер (Linux)
GOOS=linux  GOARCH=amd64   go build -o bin/wanopt-server ./cmd/server
# Клиент (Windows)
GOOS=windows GOARCH=amd64  go build -o bin/wanopt-client.exe ./cmd/client
```

## Планы и возможные улучшения

- Контроль перегрузки BBR, как только quic-go даст публичный селектор.
- HTTP keep-alive на пути обычного HTTP-форварда (сейчас один запрос на соединение).
- Режим совместимости с MASQUE / CONNECT-UDP (RFC 9298).
- Метрики ACL по назначениям и структурированный аудит-лог.
- Более богатое прикрытие (многостраничное приложение, поддержка ETag и range) для большей достоверности.
