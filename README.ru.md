# wanopt-proxy

[English](README.md) | **Русский**

Аутентифицированный QUIC-туннель с локальными SOCKS5 и HTTP-прокси. Каждое
TCP-соединение передаётся отдельным HTTP/3 CONNECT stream; UDP использует QUIC
DATAGRAM. Клиент восстанавливает туннель в фоне, сервер проверяет ACL назначения.

Протокол v2 ограничивает потребление ресурсов, корректно отменяет операции и
сохраняет семантику пересылки. Требуются **Go 1.27.2** и **quic-go 0.64.0**.
Клиент и сервер нужно обновлять вместе.

## Возможности и ограничения

- Независимые потоки устраняют взаимное влияние повторных передач TCP-in-TCP.
  Управление перегрузкой и окно соединения остаются общими: потоки конкурируют.
- QUIC не гарантирует ускорения относительно прямого TCP. Результат зависит от
  CPU, RTT, потерь, размера данных и сетевого стека. В репозитории есть сравнение.
- Разрыв туннеля завершает существующие TCP-соединения. Новые запросы ожидают
  переподключения в пределах таймаута. Прозрачного восстановления TCP-сессий и
  гарантии сохранения соединения при смене сети или IP нет.
- UDP не гарантирует доставку. **Максимум полезной нагрузки - 850 байт** в обе
  стороны. Большие пакеты отклоняются с метрикой причины. Фрагментации и сборки
  нет; приложениям с более крупными UDP-пакетами нужен другой транспорт.
- Сжатие **выключено по умолчанию**. Для сжимаемых данных его можно включить на
  обоих концах. Каждый блок до 32 КиБ независимо выбирает raw или DEFLATE.
  У raw-блока остаются 5 байт заголовка и затраты пробного сжатия. TLS, видео и
  архивы обычно не выигрывают. Совместное сжатие секретов и управляемого
  атакующим открытого текста может раскрывать информацию через длину.

## Аутентификация и доступ

Клиент проверяет SHA-256 SPKI pin сервера при TLS 1.3 handshake. Затем обе стороны
подтверждают знание PSK через HMAC с TLS exporter текущего соединения. Проверка
выполняется и после TLS session resumption. Аутентификация и прикладные данные
не отправляются через 0-RTT. Билеты TLS используются при переподключении;
`disable_session_resumption: true` отключает клиентский кеш билетов.

TCP и UDP требуют успешной аутентификации. ACL проверяет порт, исходное имя и
реальный IP после DNS. Проверенный IP передаётся прямо в dial без повторного
DNS-разрешения. DNS ограничен таймаутом и числом параллельных запросов. Запрет
имеет приоритет: разрешённое доменное имя не обходит запрещённый IP. Пустые
allow-списки разрешают любые назначения, включая частные сети. Задайте правила
выходящего доступа под свой сервер. PSK общий, отдельных пользователей и
изоляции между ними нет.

Локальные прокси не имеют пользовательской аутентификации. По умолчанию они
доступны только через loopback. Другой адрес требует `allow_remote_proxy: true`
и внешних ограничений доступа. SOCKS UDP привязан к IP управляющего TCP-клиента
и его UDP-порту. Поддерживаются только SOCKS no-auth и нефрагментированные
SOCKS-датаграммы.

Дополнительный HTTP/3-сайт (`decoy.mode: builtin | proxy | dir | off`) по
умолчанию выключен. **Гарантии неотличимости нет**: активная проверка или анализ
трафика могут распознать туннель. В протоколе используются определённые CONNECT
authorities и заголовок версии. Совместимости с MASQUE CONNECT-UDP нет.

## Быстрый запуск

```sh
cp configs/server.example.yaml configs/server.yaml
cp configs/client.example.yaml configs/client.yaml
# Создаёт cert.pem/key.pem в configs, выводит PSK и pin.
# Существующие сертификат и ключ никогда не перезаписываются.
go run ./cmd/keygen -cert -out configs
```

Запишите `psk` в оба файла, `pin` и `server` в конфигурацию клиента. Сохраняйте
сертификат и закрытый ключ между перезапусками. Пути сертификата, ключа и каталога
сайта считаются относительно файла конфигурации. Не публикуйте PSK, закрытый ключ
и заполненные конфигурации. Временный сертификат требует явного
`allow_ephemeral_cert: true`; его pin меняется при каждом запуске.

```sh
go run ./cmd/server -config configs/server.yaml
go run ./cmd/client -config configs/client.yaml
curl -x socks5h://127.0.0.1:1080 https://example.com
curl -x http://127.0.0.1:8080 https://example.com
```

HTTP поддерживает keep-alive, потоковые тела, 100-continue, ранние ответы и
upgrade. CONNECT и SOCKS сохраняют TCP half-close: после FIN от одной стороны
другая может завершить передачу ответа. Таймаут бездействия продолжает действовать.

### Сервер в Docker

```sh
# Один раз на Linux после генерации файлов. Ключ остаётся закрытым для остальных.
sudo chown 10001:10001 configs/key.pem configs/cert.pem configs/server.yaml
sudo chmod 600 configs/key.pem configs/server.yaml
# UID 10001 должен иметь право прохода через каталог configs.
docker compose up --build -d
```

Сборка с закреплённым базовым образом создаёт scratch-образ с CA-сертификатами и
двумя статическими бинарниками. Процесс работает как UID/GID 10001. Compose
включает read-only root filesystem, убирает capabilities, запрещает повышение
привилегий и ограничивает журналы. Публикуется UDP 4242. Метрики на loopback
контейнера доступны только внутри его network namespace. Для внешнего сборщика
нужно явно настроить адрес и ограничить доступ. Keygen также можно запускать из
образа с отдельным writable-каталогом, принадлежащим UID 10001.

## Ограничения ресурсов

Примеры содержат все эксплуатационные настройки. Неизвестные YAML-поля,
несколько YAML-документов, неверный pin, неполная пара cert/key, недопустимые порты
и несогласованные окна приводят к отказу при запуске.

| Ограничение | По умолчанию | Область действия |
| --- | --- | --- |
| Handshake и аутентификация | 10 с | Один туннель |
| Открытие TCP и ожидание ответа | 15 с | Один запрос |
| Соединения сервера | 256 | Весь сервер, включая аутентификацию |
| Потоки прокси | 128 плюс управляющий поток | Туннель |
| Ожидающие запросы клиента | 256 | Весь клиент |
| Локальные подключения | 256 | Общий лимит HTTP и SOCKS |
| Локальный handshake / простой | 10 с / 300 с | Подключение к прокси |
| Заголовки HTTP-ответа | 120 с, 64 КиБ | Запрос |
| DNS | 5 с, 32 параллельных | Resolver сервера |
| UDP-потоки / новые потоки | 256 / 32 в секунду | Туннель |
| UDP-очереди / workers новых потоков | 128 / 4 | Туннель; у существующих потоков отдельная очередь |
| Простой UDP-потока | 60 с | Исходящий сокет |
| UDP-сессии клиента | 128 | Весь клиент |
| Максимальное окно потока / соединения | 16 / 24 МиБ | Туннель |

Окна растут по потребности. Эти настройки не являются общим лимитом памяти
процесса. Для одного пользователя или небольшого сервера уменьшайте лимиты
соединений и UDP-потоков и измеряйте RSS и CPU под ожидаемой нагрузкой. На канале
с большим bandwidth-delay product размер окна нужно сопоставлять с доступной
памятью. Переключения на BBR в приложении нет.

Остановка отменяет приём подключений, ожидающие запросы, потоки и UDP workers и
дожидается их завершения. UDP-порт освобождается для немедленного перезапуска.
Превышение лимита отклоняется. Загрузка DNS-очереди новых UDP-потоков не блокирует
существующие потоки.

## Метрики

`metrics_listen` включает Prometheus `/metrics`; пустое значение выключает его.
Доступ должен оставаться закрытым. Метки имеют ограниченное число значений,
адреса назначения в них не попадают.

- `wanopt_relay_bytes_total{dir}` обновляется по мере успешной пересылки полезных
  данных, включая HTTP и UDP. Это не объём QUIC на проводе и не коэффициент сжатия.
- `wanopt_active_streams`, `wanopt_streams_total`, `wanopt_dial_errors_total`.
- `wanopt_tunnel_connections` и `wanopt_tls_resumptions_total` описывают аутентифицированные туннели.
- `wanopt_tunnel_reconnects_total` считает попытки переподключения, в том числе после отказа аутентификации.
- `wanopt_tunnel_rtt_seconds` показывает максимальный текущий сглаженный RTT,
  `wanopt_congestion_window_bytes` - сумму окон активных туннелей.
- `wanopt_lost_packets` - gauge текущих потерь. Значение может уменьшаться при
  пересмотре QUIC-классификации потери и закрытии соединений.
- `wanopt_udp_flows`, `wanopt_udp_datagrams_total{dir}` и
  `wanopt_udp_dropped_total{reason}` показывают UDP-нагрузку и причины отказов.

Статистика соединений читается при scrape без обработки trace каждого пакета.

## Сборка и проверки

```sh
go mod verify
go vet ./...
go test ./...
go test -race ./... # Linux с CGO toolchain
GOOS=linux GOARCH=amd64 CGO_ENABLED=0 go build -trimpath -o bin/wanopt-server ./cmd/server
GOOS=windows GOARCH=amd64 CGO_ENABLED=0 go build -trimpath -o bin/wanopt-client.exe ./cmd/client
```

CI запускает тесты Linux и Windows, race detector на Linux, короткие fuzz-тесты,
govulncheck, сборки бинарников и Docker. Регрессии используют настоящие локальные
QUIC/TLS, TCP и UDP. Проверяются запрет UDP до аутентификации, предел QPACK,
отмена, возврат ёмкости после ошибок, перезапуск, pin при TLS resumption,
HTTP/SOCKS и повреждённые данные протокола.

[Инструкция по бенчмаркам](docs/benchmarks.md) описывает сравнение прямого TCP,
TCP relay и QUIC при заданных RTT и потерях. Локальные измерения не заменяют
длительный тест в сети развёртывания.

## Обновление с v1

1. Сохраните прежние бинарники, конфигурации и постоянный ключ.
2. Обновите обе стороны вместе. v2 заменяет перехват нестандартных потоков на
   HTTP/3 CONNECT и меняет формат сжатия. Совместимости с v1 нет. Действующие
   TCP-соединения при обновлении завершатся.
3. Перенесите адреса, PSK, pin и ACL в новые примеры. Постоянный сертификат
   создавайте только при отсутствии прежнего; смена ключа требует нового pin.
   Сжатие и дополнительный сайт по умолчанию выключены.
4. Старые `allow_0rtt` и `enable_0rtt` принимаются, но игнорируются. Для билетов
   TLS используется `disable_session_resumption`. ALPN должен быть `h3`.
5. Обновите панели метрик с учётом семантики RTT, потерь и TLS resumption.
   Проверьте размеры UDP своих приложений. Для отката восстанавливайте обе
   стороны v1 и их настройки вместе.

[Разбор транспортов для большого RTT](docs/high-latency.md) сопоставляет QUIC/BBR,
KCP, SRT и Hysteria и описывает методику облачных тестов. Исправлен обычный
HTTP-прокси: он теперь учитывает `compression: true`, а при отказе сервера
от сжатия продолжает передавать данные без него. По умолчанию сжатие выключено.


Общие лимиты, адаптивное сжатие, ротация PSK/pin, серверный SIGHUP, выбор Reno/BBR и методика измерений: [эксплуатация и ограничения](docs/operations.md).
